## 배포하는 법

1. 버전 올리기: `package.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml`의 version
2. 커밋 후 `git tag vX.Y.Z && git push origin vX.Y.Z` (개인 계정 epww1502로 push)
3. GitHub Actions가 맥 2종(서명·공증)·윈도우를 빌드하고, 셋 다 성공하면 `latest.json`을 만들어 공개한다. 하나라도 실패하면 초안으로 남고 최신 링크는 이전 버전 그대로.
4. 맥 공증은 보통 몇 분, Apple 서버가 느리면 수십 분. 진행 확인:
   `xcrun notarytool history --key <AuthKey.p8 경로> --key-id <키 ID> --issuer <Issuer ID>`

## 비밀 값 (어디 있는지만 — 내용은 여기 적지 않는다)

| 무엇 | 어디 | 용도 |
|---|---|---|
| Developer ID 인증서 `.p12` + 비밀번호 | 이 맥의 문서 폴더, 키체인 | 맥 앱 서명 |
| App Store Connect API 키 `.p8` + 키 ID + Issuer ID | 이 맥의 다운로드 폴더 | 맥 공증 |
| 자동 업데이트 서명 키 + 비밀번호 | 이 맥의 `~/.tauri/mochi-pet.key` | 업데이트 파일 서명 (잃어버리면 이후 업데이트 불가 — 꼭 백업) |
| 위 값들 전부 | GitHub 저장소 Settings → Secrets | 릴리스 빌드가 사용 |

- 배포는 GitHub에서 하므로 다른 컴퓨터에서는 키 파일 없이 태그만 올리면 된다.
- 키를 다시 등록할 땐: `sh scripts/set-apple-secrets.sh <p12> <p8>`, `sh scripts/setup-updater-key.sh`
- 위 파일들은 저장소에 절대 넣지 않는다(`.gitignore`에 `*.p12`, `*.p8`, `*.key`).

## 다른 컴퓨터에서 개발 이어서 하기

```bash
git clone https://github.com/epww1502/mochi-pet.git && cd mochi-pet
npm install
npm run dev          # 브라우저로 화면만 (?away ?update ?climb ?weather=rain 등)
npm run tauri dev    # 실제 앱 (Rust 필요: rustup)
npm test && cargo test --manifest-path src-tauri/Cargo.toml
```

- 이 저장소는 개인 GitHub 계정(epww1502) 것. 회사 계정과 섞이지 않게 저장소 안에서만 `git config user.name epww1502`, 이메일은 GitHub noreply 주소로.
- 서버: Supabase 프로젝트(서울). 테이블 rooms / messages / room_members / room_tree는 RLS로 잠겨 있고 함수(create_room, join_room, send_message, recent_messages, touch_member, list_members, leave_room, add_ornament, list_ornaments, clear_tree)로만 접근한다.

## 지금까지 정한 것 (왜 이렇게 했나)

- Claude Code 연동은 뺐다. 친구끼리 상태 보고 채팅하는 펫으로 정리하고 이름을 claude-pet → mochi-pet으로 바꿨다.
- Tauri + React: 채팅 한글 입력 때문에 순수 Rust(egui) 대신 웹뷰를 쓴다.
- 로그인 없음: 방 id를 아는 사람이 멤버. 친구끼리 쓰는 용도라 단순하게 두었다.
- 채팅은 WebRTC 대신 Supabase Realtime: 속도 차이가 작고 회사망 UDP 차단·중계 서버 비용 문제가 있어서. 대신 "먼저 보내고 저장은 뒤에서"로 체감 속도를 올렸다.
- 온라인 판단: 실시간 연결 + 1분마다 남기는 접속 기록. 최근 3분 안에 기록이 있으면 온라인.
- 펫 창은 화면 작업 영역 전체를 덮는 투명 창이고, 클릭은 펫 위에서만 받는다.
